# 2026-10-28 — S25U KernelSU LKM 攻关（通宵）

## 目标
在 S9380(S25U, 6.6.98 abogki) 上跑 KernelSU，先靠 GhostLock/CVE-2026-43499 拿到临时 root，再 insmod kernelsu.ko。

## 已完成（关键结论）
1. **源码/vmlinux**：V100 `/data/ksrc-6.6.98`（AOSP 6.6.98 + 设备 .config `s25u.config`），03:56 编完 vmlinux + Module.symvers。
2. **kernelsu.ko**：`/data/tools/KernelSU`（官方 tiann/KernelSU v3.2.5 + 本地 Samsung KDP compat），用 NDK r27c LLVM=1 编，vermagic 与设备完全一致。
3. **CRC 校验（自己实现的）**：
   - 从设备 `Image` 反推 `__ksymtab`/`__kcrctab` 段边界，按 index 读出设备真实 CRC 表 → 与 .ko 的 `__versions` 比对：**100 项中 79 匹配、21 不匹配**。
   - 不匹配项：module_layout / kmalloc_caches / kmalloc_trace / fget / fput / filp_close / noop_llseek / __put_task_struct / __get_task_comm / __alloc_pages / __free_pages / crypto_* / param_ops_bool / kobject_del / module_put / try_module_get / kernel_read / kernel_write / _copy_to_iter。
4. **BTF 交叉验证**：设备 `/sys/kernel/btf/vmlinux` 已拉回，与本地 .BTF 比对：cred / module / file / kernel_param / kmem_cache / crypto_shash / page / inode / mount / super_block / path / dentry / seq_file / nsproxy / user_namespace / signal_struct / mm_struct / vm_area_struct / pid **全部结构一致**；`task_struct` 只有尾部 kabi 区不同（`android_vendor_data2` 替换 `android_kabi_reserved1`，偏移从 kretprobe_instances=3576 起 +8，KSU 用到的字段都在前面，安全）。
5. **真正的坑：三星裁剪导出符号**。设备只有 13020 个 `__ksymtab` 导出，kernelSU 需要但设备没导出的有 **64 个**（59 函数 + 5 数据：init_mm / selinux_state / selinux_blob_sizes / mntns_operations / __tracepoint_sys_enter）。
6. **解决方案（已实测有效）：预链接 (prelink)**
   - `kptr_restrict` 写 0 后 root 能读到 /proc/kallsyms 真实地址；
   - 脚本 `/tmp/prelink.py`：把 .ko 里 **UND 符号直接改写成 `SHN_ABS` + 运行时地址**（内核 simplify_symbols 对 SHN_ABS 不做处理，relocation 直接用 st_value，且**跳过 CRC 校验**）；
   - 实测 ksymtest.ko 与 **kernelsu.ko 都 insmod 成功**（`lsmod` 里能看到 `kernelsu 172032 0`），无 panic。
   - 脚本：`/tmp/patchko.py`（改 CRC）、`/tmp/prelink.py`（改 ABS）、`/tmp/kallsyms.txt`（设备全量 kallsyms，18MB）。
   - V100 上有 `/data/ksymtest`（kprobe 解析符号验证工程，实测 kallsyms_lookup_name/commit_creds/filp_open 等全部可解析）。

## 2026-10-28 05:52 结果：成功 ✅
- 手机并没有重启（uptime 3.4 天），只是 USB 重新枚举 → adb 授权掉了。
- 预链接的 `kernelsu-abs.ko` **稳定加载**，KernelSU manager v3.2.5 显示 **「工作中 <LKM> [越狱模式]」版本 32525-2**。
- 但 KSU 加载后 SELinux 变 Enforcing，exploit 的 temp_su.sock（u:r:kernel:s0）被挡 → 没有 root 通道。
- **突破方法**：用 manager UI 装了一个自制 KSU 模块 `roothelper.zip`（module.prop + customize.sh），customize.sh 以 **uid=0 / u:r:ksu:s0** 执行，里面 `setenforce 0` → 立刻恢复 Permissive，exploit 的 root shell 又能用了。
  - 模块安装路径：manager → 模块 → 右下 + → 文件选择器 → /sdcard/Download/roothelper.zip。
  - 产物 `/tmp/roothelper.zip`（598 B）。
- 现状：root shell 可用（`echo "<cmd>" | /data/local/tmp/cve-2026-43499-root`，context u:r:kernel:s0，Permissive）。
- **三星 DEFEX 仍在拦**：dmesg 显示 `[DEFEX] Immutable root violation ... /data/adb/ksu/bin` 和 `Safeplace violation ... /data/adb/ksud` → ksud 被杀、/system/bin/su 兼容层不生效（sucompat hook 未装上）。KSU 对 App 提权是正常的（dmesg 有 `allow root for: 10453`）。
- 待办：① 持久化（重启后 KSU/root 全没，需开机自启 exploit 或利用 manager 的「自动越狱：开机检测到 Permissive SELinux 时自动 Magica 提权」）；② DEFEX 绕过（compat/samsung_defex.c 已编进模块但没完全生效）；③ 再谈 PoGo/LSPosed。

## 当前卡点（历史）
- KSU 一加载就把 SELinux 切回 **Enforcing**，exploit 的 `/data/local/tmp/temp_su.sock`（root 上下文 u:r:kernel:s0）从 shell 连不上（Permission denied）→ 失去 root 通道。
- 之后 S25U 从 adb 掉了（USB 重新枚举，/dev/bus/usb 上还在，MTP 模式）→ 大概率手机重启，**root 与已加载的 KSU 都没了**。
- 已下载好官方 manager：`/tmp/KernelSU_v3.2.5.apk`（9,083,665 bytes，ZIP 校验 OK）。
